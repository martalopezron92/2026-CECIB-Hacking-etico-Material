## 3. Conceptos clave para entender la alerta

La alerta utiliza vocabulario técnico. Antes de leerla, revise los siguientes conceptos. **No es necesario dominarlos en profundidad**, sino entender la idea general para poder explicarla.

### 3.1 Conceptos generales

| Concepto | Explicación sencilla |
|---|---|
| **Servidor web** | Ordenador que está conectado permanentemente a internet y entrega las páginas web a quien las visita. |
| **PHP** | Lenguaje de programación que se ejecuta **en el servidor**. Prepara la página (por ejemplo, consulta una base de datos) antes de enviarla al navegador del usuario. Es uno de los lenguajes más usados en la web; por ejemplo, WordPress está hecho en PHP. |
| **Petición** (*request*) | Cada vez que alguien visita una página, su navegador envía una petición al servidor, y este responde. |
| **Proceso trabajador** (*worker*) | Para ir más rápido, PHP reutiliza el mismo "trabajador" para atender varias peticiones seguidas, una detrás de otra. |
| **Memoria** | Espacio de trabajo temporal que usa un programa mientras funciona. Cuando termina de usar una parte, la **libera** (la devuelve para que se use en otra cosa). |

### 3.2 Conceptos de seguridad

| Concepto | Explicación sencilla |
|---|---|
| **Vulnerabilidad** | Fallo o debilidad en un programa que un atacante puede aprovechar para hacer algo que no debería poder hacer. |
| **CVE** (*Common Vulnerabilities and Exposures*) | Código único que identifica públicamente una vulnerabilidad, con el formato `CVE-año-número`. Sirve para que todo el mundo hable del mismo fallo sin confusiones. |
| **Explotar una vulnerabilidad** | Aprovechar el fallo para realizar un ataque. |
| **Falta de memoria** (*out of memory*, OOM) | Situación en la que un programa se queda sin memoria disponible y tiene que interrumpir lo que estaba haciendo. |
| **Corrupción de memoria** | Los datos guardados en memoria quedan en un estado incorrecto o incoherente. Es peligroso porque el programa puede comportarse de forma imprevisible. |
| **Ejecución remota de código** (*Remote Code Execution*, RCE) | El atacante consigue que el servidor ejecute las órdenes que él quiera, desde cualquier lugar a través de internet. Es una de las consecuencias más graves posibles. |
| **No autenticada** | El atacante **no necesita usuario ni contraseña** para lanzar el ataque. |
| **Actualización / parche** | Nueva versión del programa que corrige el fallo. |
| **Mitigación temporal** | Medida provisional que reduce el riesgo mientras no se puede actualizar. |
| **Puerta trasera** (*backdoor*) | Acceso oculto que un atacante deja instalado para volver a entrar más tarde. |
| **Expuesto a internet** | Sistema que es accesible desde cualquier lugar de internet, no solo desde la red interna de la empresa. |

### 3.3 Una analogía para entender las dos vulnerabilidades

Imagine un **restaurante** (el servidor) donde un mismo **camarero** (el proceso trabajador) atiende una mesa tras otra (las peticiones).

- **Primera vulnerabilidad (CVE-2026-109618):** el camarero está preparando una mesa y, a mitad de la tarea, le interrumpen bruscamente porque se ha quedado sin espacio en la bandeja (falta de memoria). La mesa queda **a medio preparar**. Después, al recoger, se trata esa mesa como si estuviera correctamente montada, aunque no lo está.
- **Segunda vulnerabilidad (CVE-2026-109619):** cuando un cliente se marcha, se retira su mesa, pero queda olvidada **una nota con información del cliente anterior**. El siguiente cliente que atiende ese mismo camarero llega, y el camarero utiliza esa nota antigua antes de que se limpie todo.

En ambos casos, el problema es que el programa **confía en datos que no son válidos**. Un atacante que sepa provocar estas situaciones puede, en determinadas condiciones, aprovecharlas para tomar el control del servidor.

> Esta analogía es una simplificación con fines didácticos. Puede utilizarla (o crear la suya propia) en su presentación.

## 5. Introducción: ¿qué es Marp y cómo funciona?

### 5.1 Definición

**Marp** (*Markdown Presentation Ecosystem*) es un conjunto de herramientas de código abierto que permite crear presentaciones de diapositivas escribiendo exclusivamente texto en formato Markdown. El autor se concentra en el contenido, mientras que Marp transforma ese texto en diapositivas con un diseño coherente.

### 5.2 Principio de funcionamiento

1. **Redacción:** se escribe un archivo `.md` con sintaxis Markdown estándar (títulos, listas, imágenes, tablas…).
2. **Interpretación:** Marp divide el contenido en diapositivas y aplica un **tema** (una hoja de estilos CSS).
3. **Renderizado y exportación:** el resultado puede exportarse a HTML, PDF, PowerPoint (PPTX) o imágenes.

Internamente, cada diapositiva se convierte en un elemento HTML `<section>`. Este dato es fundamental, porque permite dar estilo a las diapositivas con CSS como si fueran una página web.

### 5.3 Ventajas en un entorno técnico

| Aspecto | Herramientas tradicionales | Marp |
|---|---|---|
| Formato del archivo | Binario o XML complejo | Texto plano (`.md`) |
| Control de versiones (Git) | Difícil comparar cambios | Totalmente compatible |
| Coherencia visual | Depende del autor | Garantizada por el tema |
| Reutilización de estilos | Plantillas propietarias | CSS estándar |
| Rapidez de elaboración | Mucho tiempo en el diseño | El foco está en el contenido |

Esta última ventaja es especialmente útil en ciberseguridad: cuando aparece una alerta, hay que comunicarla **rápido**, y disponer de un tema corporativo ya preparado permite centrarse solo en el contenido.

### 5.4 Elementos relevantes de un documento Marp

| Elemento | Función | Ejemplo |
|---|---|---|
| **Front-matter** | Bloque inicial que activa Marp y define opciones globales | `marp: true` |
| **Separador de diapositivas** | Línea con tres guiones que inicia una nueva diapositiva | `---` |
| **Directivas** | Instrucciones que modifican el aspecto o comportamiento | `<!-- paginate: true -->` |
| **Temas y estilos** | Reglas CSS que definen el diseño visual | `theme: gaia` |

## 7. Fase 1 — Primera presentación

### 7.1 Activar Marp en el documento

Abra `presentacion.md` y escriba:

```markdown
---
marp: true
---

# Alerta de seguridad crítica en PHP

CVE-2026-109618 y CVE-2026-109619

---

## ¿Qué es PHP?

Un lenguaje de programación que se ejecuta en el servidor web y prepara las páginas antes de enviarlas al navegador.

---

## ¿Qué ha pasado?

- El NCSC ha publicado una alerta el 21/10/2026
- PHP ha publicado una actualización de seguridad
- El fallo permite atacar servidores web
```

**Explicación:**

- El bloque delimitado por `---` al inicio es el **front-matter**. La línea `marp: true` es obligatoria para que el documento se trate como presentación.
- Cada `---` posterior **separa una diapositiva** de la siguiente.
- El resto es Markdown convencional.

### 7.2 Abrir la vista previa

Pulse `Ctrl + K` y, a continuación, `V`. Se abrirá un panel lateral con las diapositivas, que se actualiza al escribir.

**Comprobación:** la vista previa muestra tres diapositivas. Si aparece como documento continuo, revise la línea `marp: true`.

### 7.3 Elementos de Markdown en una diapositiva técnica

Añada una diapositiva que resuma las vulnerabilidades en una tabla:

```markdown
---

## Las dos vulnerabilidades

| Código | ¿Qué falla? |
|---|---|
| CVE-2026-109618 | Al quedarse sin memoria, PHP deja datos *a medio preparar* |
| CVE-2026-109619 | Restos de una petición anterior se reutilizan por error |

> **Consecuencia:** un atacante podría ejecutar órdenes en el servidor **sin contraseña**.
```

**Comprobación:** la tabla, la cursiva, la negrita y la cita se visualizan correctamente.

## 8. Fase 2 — Directivas globales y locales

### 8.1 Directivas globales

Afectan a toda la presentación y se escriben en el front-matter. Modifique el inicio del archivo:

```markdown
---
marp: true
theme: default
size: 16:9
paginate: true
header: 'Alerta de seguridad · PHP'
footer: 'Departamento técnico · Octubre 2026'
---
```

| Directiva | Función | Valores habituales |
|---|---|---|
| `theme` | Tema visual | `default`, `gaia`, `uncover` o un tema propio |
| `size` | Proporción de la diapositiva | `16:9`, `4:3` |
| `paginate` | Muestra el número de diapositiva | `true`, `false` |
| `header` | Texto en la cabecera | Cualquier texto |
| `footer` | Texto en el pie | Cualquier texto |

**Actividad 8.1:** pruebe los temas `default`, `gaia` y `uncover`. ¿Cuál considera más adecuado para comunicar una alerta de seguridad y por qué?.

### 8.2 Directivas locales

Se aplican desde la diapositiva en la que se escriben **en adelante**, mediante comentarios HTML:

```markdown
---

<!-- backgroundColor: #1b1b2f -->
<!-- color: white -->

## ¿Cuál es el problema?
```

Observe que **todas las diapositivas siguientes** heredan el fondo oscuro.

### 8.3 Directivas de ámbito puntual (prefijo `_`)

Con un guion bajo delante, la directiva afecta **solo a la diapositiva actual**. Es ideal para una diapositiva de aviso:

```markdown
---

<!-- _backgroundColor: #c1121f -->
<!-- _color: white -->
<!-- _paginate: false -->
<!-- _header: '' -->

# Nivel de riesgo: CRÍTICO
```

**Actividad 8.2:** cree una diapositiva de separación de sección para cada bloque de la presentación ("¿Qué ha pasado?", "El problema", "¿Qué hacer?"), sin numeración ni cabecera, y compruebe que la siguiente diapositiva recupera el aspecto normal.

### 8.4 Notas del presentador

Cualquier comentario HTML que no sea una directiva se convierte en **nota del presentador**. No aparece en la diapositiva, pero sí en la exportación HTML y PPTX:

```markdown
## ¿A quién afecta?

Todas las versiones de PHP.

<!-- Insistir en que no basta con revisar las versiones antiguas: hay que localizar TODAS las instalaciones de PHP. -->
```

Las notas son muy útiles en este caso: permiten mantener las diapositivas sencillas y guardar la explicación detallada para decirla en voz alta.

**Comprobación:** la presentación muestra numeración, cabecera y pie; las diapositivas de sección y de aviso tienen un aspecto diferenciado.

## 9. Fase 3 — Imágenes, fondos y maquetación

Guarde en `img/` al menos dos imágenes relacionadas con el tema (servidores, código, candados, etc.).

> **Importante:** utilice imágenes con licencia libre (por ejemplo, de Unsplash, Pexels o Wikimedia Commons) o creadas por usted mismo, e indique su procedencia en la diapositiva de fuentes.

### 9.1 Redimensionar imágenes

```markdown
![width:400px](img/servidor.jpg)
![height:200px](img/servidor.jpg)
![w:300 h:200](img/servidor.jpg)
```

### 9.2 Imágenes de fondo

La palabra clave `bg` convierte una imagen en fondo:

```markdown
---

![bg](img/servidor.jpg)

# Alerta de seguridad en PHP
```

| Sintaxis | Efecto |
|---|---|
| `![bg cover](...)` | Cubre toda la diapositiva (por defecto) |
| `![bg contain](...)` | La imagen completa cabe sin recortarse |
| `![bg 50%](...)` | Escala la imagen al porcentaje indicado |

### 9.3 Filtros de imagen

Para que el texto se lea bien sobre una foto, conviene oscurecerla o desenfocarla:

```markdown
![bg brightness:0.3](img/servidor.jpg)
![bg blur:3px](img/servidor.jpg)
![bg grayscale](img/servidor.jpg)
```

### 9.4 Composición a dos columnas

```markdown
---

![bg left:40%](img/codigo.jpg)

## ¿Qué es PHP?

- Lenguaje que se ejecuta en el **servidor**
- Prepara la página antes de enviarla
- Se usa en una gran parte de las webs
```

Sustituya `left` por `right` para invertir la disposición.

### 9.5 Representar un proceso sin imágenes

No siempre hace falta una imagen. Una secuencia sencilla puede explicar cómo funciona el ataque:

```markdown
---

## ¿Cómo podría producirse el ataque?

1. El atacante provoca que PHP **se quede sin memoria**
2. PHP se interrumpe y la memoria queda **en mal estado**
3. En ciertas condiciones, el atacante lo aprovecha…
4. …para **ejecutar órdenes en el servidor** sin contraseña
```

**Actividad 9.1:** cree una portada con imagen de fondo oscurecida y título en blanco, y una diapositiva "¿Qué es PHP?" con composición imagen-texto.

**Comprobación:** las imágenes se cargan (las rutas son relativas al archivo `.md`) y el texto es legible.

## 10. Fase 4 — Estilos CSS dentro del documento

### 10.1 Estilos globales con `<style>`

Añada este bloque justo después del front-matter:

```markdown
<style>
section {
  font-family: 'Segoe UI', Arial, sans-serif;
  font-size: 28px;
}

h1 {
  color: #1b1b2f;
}

h2 {
  color: #c1121f;
  border-bottom: 3px solid #c1121f;
}

em {
  color: #c1121f;
  font-style: normal;
  font-weight: bold;
}

code {
  background: #f1f1f1;
  color: #1b1b2f;
}
</style>
```

### 10.2 Correspondencia entre Markdown y etiquetas HTML

| Markdown | Etiqueta HTML | Selector CSS |
|---|---|---|
| `# Título` | `<h1>` | `h1` |
| `*cursiva*` | `<em>` | `em` |
| `**negrita**` | `<strong>` | `strong` |
| `` `código` `` | `<code>` | `code` |
| `> cita` | `<blockquote>` | `blockquote` |
| `- elemento` | `<ul><li>` | `ul`, `li` |
| `1. elemento` | `<ol><li>` | `ol`, `li` |
| Tabla | `<table>` | `table`, `th`, `td` |
| Diapositiva | `<section>` | `section` |
| Cabecera / pie | `<header>` / `<footer>` | `header`, `footer` |

> **Ejemplo práctico:** con la regla `em` anterior, todo lo que escriba en *cursiva* se mostrará en rojo y negrita. Así puede resaltar términos clave como *ejecución remota de código* sin escribir HTML.

### 10.3 Estilos de una sola diapositiva con `<style scoped>`

```markdown
---

<style scoped>
blockquote {
  border-left: 8px solid #c1121f;
  background: #fde8e8;
  padding: 20px;
}
</style>

## Consecuencia

> Un atacante podría ejecutar órdenes en el servidor sin necesidad de contraseña.
```

### 10.4 Clases personalizadas

La directiva `class` asigna una clase CSS a una diapositiva:

```markdown
<style>
section.alerta {
  background: #c1121f;
  color: white;
  text-align: center;
  justify-content: center;
}

section.alerta h1 {
  color: white;
}
</style>

---

<!-- _class: alerta -->

# ¡Actualizar PHP cuanto antes!
```

**Actividad 10.1:** defina las clases `portada`, `alerta` y `cierre`, y aplíquelas a las diapositivas correspondientes.

**Comprobación:** los estilos globales afectan a todas las diapositivas; los `scoped` y las clases, solo a las indicadas.

## 11. Fase 5 — Creación de un tema propio en un archivo externo

Cuando un departamento comunica alertas con frecuencia, lo lógico es disponer de un **tema reutilizable**: cada nueva alerta solo requiere escribir el contenido. En Marp, el CSS externo se define como **tema**.

> **Importante:** en Marp no se enlaza un CSS con `<link>`, como en una página web. El archivo se declara como tema y se registra en la configuración del editor.

### 11.1 Crear el archivo del tema

Cree `themes/ciberseguridad.css`:

```css
/* @theme ciberseguridad */

@import 'default';

section {
  font-family: 'Segoe UI', Arial, sans-serif;
  background: #ffffff;
  color: #222222;
  padding: 60px;
}

h1 {
  color: #1b1b2f;
  font-size: 54px;
}

h2 {
  color: #c1121f;
  border-bottom: 3px solid #c1121f;
  padding-bottom: 8px;
}

em {
  color: #c1121f;
  font-style: normal;
  font-weight: bold;
}

code {
  background: #eeeeee;
  color: #1b1b2f;
  padding: 2px 6px;
  border-radius: 4px;
}

blockquote {
  border-left: 8px solid #c1121f;
  background: #fde8e8;
  padding: 16px 24px;
  color: #222222;
}

header,
footer {
  color: #888888;
  font-size: 18px;
}

section::after {
  color: #c1121f;
  font-weight: bold;
}

/* Portada */
section.portada {
  background: #1b1b2f;
  color: #ffffff;
  justify-content: center;
}

section.portada h1 {
  color: #ffffff;
}

/* Separador de sección */
section.seccion {
  background: #1b1b2f;
  color: #ffffff;
  justify-content: center;
  text-align: center;
}

section.seccion h1 {
  color: #ffffff;
}

/* Diapositiva de aviso */
section.alerta {
  background: #c1121f;
  color: #ffffff;
  justify-content: center;
  text-align: center;
}

section.alerta h1,
section.alerta h2 {
  color: #ffffff;
  border: none;
}

/* Ficha de vulnerabilidad */
section.cve h2 {
  font-family: 'Consolas', monospace;
}
```

**Elementos clave:**

- `/* @theme ciberseguridad */` — comentario **obligatorio** que define el nombre del tema.
- `@import 'default';` — hereda un tema base, de modo que solo se definen las diferencias.
- `section::after` — pseudo-elemento que muestra el número de página.

### 11.2 Registrar el tema en VS Code

Edite `.vscode/settings.json`:

```json
{
  "markdown.marp.themes": [
    "./themes/ciberseguridad.css"
  ]
}
```

## 17. Anexo B — Resolución de problemas frecuentes

| Problema | Causa probable | Solución |
|---|---|---|
| Se muestra un documento normal, no diapositivas | Falta `marp: true` o está mal escrito | Revise el front-matter |
| El tema propio no se aplica | El nombre en `theme:` no coincide con `/* @theme */` | Use exactamente el mismo nombre |
| El tema no se reconoce | No está registrado o la ruta es incorrecta | Revise `.vscode/settings.json` y que la carpeta del proyecto esté abierta |
| Los cambios en el CSS no se reflejan | La vista previa no se ha recargado | Guarde el CSS y reabra la vista previa |
| Las imágenes no aparecen | Ruta incorrecta | Las rutas son relativas al `.md`; revise mayúsculas y extensión |
| No se puede exportar a PDF o PPTX | Falta un navegador compatible | Instale Chrome, Edge o Firefox |
| Una directiva afecta a demasiadas diapositivas | Falta el prefijo `_` | Use `<!-- _directiva: valor -->` |
| Aparece una diapositiva vacía al principio | Hay contenido antes del front-matter | El primer `---` debe estar en la primera línea |
| Los emojis no se ven en el PDF | Fuente sin soporte de emojis | Sustitúyalos por texto o pruebe otro navegador para exportar |
